# Dashboards

Every file here becomes one ConfigMap (kustomization.yaml), labelled
`grafana_dashboard: "1"`, and Grafana's sidecar loads it into the folder named
by its `grafana_folder` annotation. Provisioned dashboards are read-only in
the UI: Save As a copy, iterate, Export → JSON model with "export for sharing
externally" **off**, drop the file in its folder directory, add a generator
entry, PR. The copy disappears on the next Grafana restart. A file's
`grafana_folder` is its directory, nested folders included (`Kubernetes/Alloy`,
`Kubernetes/vendored`); `test_dashboards.py` enforces it.

A `vendored/` subfolder in a folder holds upstream dashboards kept for
reference. Most are replaced by a hand-written dashboard in the parent folder,
which is the one the folder overview and the Glance tiles link to; a vendored
copy takes " (vendored)" in its title only where the title would clash with its
replacement's (Kubernetes overview, Nodes). Node Exporter Full has no
replacement: it is the layout reference for the host template.

NetBox joins: a table that names a host, VM or address it knows adds NetBox
datasource queries keyed on the table's own column (lowercased through the
query's join key) and joins them `outerTabular`, so the identity reads from
NetBox at view time. Each trap below empties the NetBox columns silently, and
`test_dashboards.py` fails on each. The panel datasource is Mixed and every
target names its own, or the NetBox queries never run. A query filter is an
explicit refId list, and only the first merge or join carries one, because a
combined frame has no refId. A `renameByRegex` strips the ` netbox_<type>`
suffix the join adds to NetBox fields. The null-row filter runs last, on a
renamed metric header. A record query returns `display_url`, hidden by an
override, because the plugin builds the record cell's link from it.

Vendoring: `python3 vendor.py <Folder>/<name>.json --id <grafana.com id>`
pins every datasource reference to the provisioned UIDs (`prometheus`,
`loki`) and strips `__inputs`. Datasources with other UIDs will show
"datasource not found". No Cilium dashboards are provisioned: the chart's
are off (`dashboards.enabled` in `kubernetes/clusters/homelab/cilium/app/values.yaml`) because
most of their queries return nothing here; see `docs/design/observability.md`.

Host dashboards: `Hosts/<host>.json` is generated for every physical host, the
four NUCs and the eight Pis. Edit `templates/host.json` (the dashboard, with
`__HOST__` for the host name and `__<KEY>__` for a string setting) or
`templates/hosts.json` (each host's `fans`, `power`, `smart`, `coretemp` and
`proxmox` flags, its main filesystem `rootfs`, its Loki selector `logs` and
that stream's level label `loglevel`), then run `python3 hosts.py`. A panel,
row or dashboard link carrying `"homelabRequires": "<flag>"` is dropped for a
host whose flag is false, so a Pi shows no empty Fans, Power or CPU-core rows
and no Proxmox link; one carrying `"homelabUnless": "<flag>"` is kept only
where the flag is false, which fills the power slot of a Pi's Summary row with
its CPU clock. Panels below a dropped one move up, so a generated file has no
empty rows. `test_hosts.py` fails while a committed host file is stale or
leaves a gap. `templates/` holds no ConfigMap. Under the Summary row, a NetBox table shows
the host's NetBox device record (role, model, site, platform, status, primary
address, description; the NetBox cell links to it), matched on the host name
without case. The layout follows the vendored
Node Exporter Full: Summary gauges and small stats, one panel each for CPU,
memory, network and disk, then CPU and memory, System, Temperatures, Fans,
Power, SMART, Storage, Network and Logs. A panel a host cannot fill carries a
flag rather than reading "No data" there. A Pi's SMART row reads its USB NVMe
drive (`device="sda"`) from the `smartctl` DaemonSet. `Hosts/voyager.json` is
hand-written in the same order.
